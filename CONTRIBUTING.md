# Contribuer à Campus Agenda

## Branches et commits

- Partir de `main` et créer une branche courte par fonctionnalité.
- Préférer des commits petits, cohérents et descriptifs.
- Ouvrir une revue avant la fusion d'une fonctionnalité importante.
- Mettre à jour les tests et la documentation avec le code.

## Données et confidentialité

- Ne jamais ajouter de nom d'élève, adresse, identifiant réel, code de classe actif ou donnée scolaire réelle.
- Utiliser des exemples fictifs clairement identifiés, comme `classe-demo` ou `eleve-test-001`.
- Ne jamais versionner `.env.local`, une clé, un jeton, une sauvegarde ou un export de base de données.
- Vérifier les fichiers préparés avant chaque commit.

## Qualité attendue

- Contrôler les droits côté serveur, jamais uniquement dans l'interface.
- Tester l'isolation entre classes et les permissions de modification.
- Préserver l'accessibilité et la lisibilité sur mobile.
